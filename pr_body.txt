## Acceptance Criteria

- Key rotation generates a new encryption key via the OS keychain API
- All existing credentials are re-encrypted with the new key
- Credentials encrypted with the old key are still readable during the migration window
- After rotation completes, old key is removed from the keychain
- Key version is tracked and stored credentials reference their encryption key version
- Rotation is atomic: if it fails mid-process, credentials remain accessible with the old key
- Developer menu item triggers rotation with a confirmation dialog
- CLI command outputs rotation progress and results
- Tests verify round-trip encryption after rotation and atomic rollback on failure
